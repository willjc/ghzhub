## 二、阻断项（🔴 必须修复）

### 1. H5 端越权（最严重）

**问题：** `HzEnterpriseBillAppController` 中以下接口**仅按 billId 操作，未校验调用者手机号与账单 contactPhone 是否一致**：

```
GET  /h5/app/enterpriseBill/{billId}              ← getInfo
GET  /h5/app/enterpriseBill/checkinInfo/{billId}  ← 详情含人员名单文件
POST /h5/app/enterpriseBill/pay                   ← 支付
POST /h5/app/enterpriseBill/submitCheckin         ← 上传人员名单
POST /h5/app/enterpriseBill/submitCheckout        ← 申请退租
```

**风险：** 任何已登录用户只要枚举 billId（自增 Long），即可看到任意企业的合同、人员名单文件路径、批次信息；甚至替别的企业"提交退租"。

**建议修复方向：**
- 所有按 billId 的接口，需在 Service 层先 `selectEnterpriseBillById`，比对 `bill.contactPhone == 当前登录用户.phone`，否则返回 403
- `phone` 不应再作为前端可控参数，直接从 `SecurityUtils.getLoginUser().getUser().getPhonenumber()` 取
- 建议补一个 `@interface BillOwnerCheck` AOP 注解统一处理

### 2. 支付为空壳

**位置：** `HzEnterpriseBillAppController#pay`（第 220-237 行）

```java
// 简单实现：直接标记为已支付
// 实际项目应对接支付接口
int result = enterpriseBillService.payBill(billId, payMethod != null ? payMethod : "在线支付", transactionNo);
```

**问题：** `transactionNo` 来自前端、未校验真实性，相当于"客户端说自己付过钱就行"。

**建议方向：**
- 微信支付：客户端调用 `wx.requestPayment` → 后端创建预下单 → 接收支付回调验签后才更新 `billStatus='2'`
- 若短期内不接通道：至少补上"线下转账凭证上传" + 后台审核流程

## 三、严重项（🟠 强烈建议本期或下期修复）

### 3. 文件上传无白名单

**位置：** `submitCheckin` 后端、`enterprise.vue#handleChooseFile` 前端  
- 后端 `FileUploadUtils.upload` 调用未传扩展名白名单参数（应使用 `MimeTypeUtils.DEFAULT_ALLOWED_EXTENSION` 之类约束）
- 前端 `accept=".xlsx,.xls,.rar,.zip,.doc,.docx,.pdf,.jpg,.jpeg,.png"` 接受压缩包，恶意脚本可包装上传
- 未限制单文件大小

### 4. `downloadTemplate` 在 jar 部署下崩溃

**位置：** `HzEnterpriseBillAppController#downloadTemplate`  
```java
File file = resource.getFile();  // ❌ jar 内 classpath 资源不能转 File
```
**修复：** 改为 `resource.getInputStream()` 直接 copy 到 response。

### 5. `saveWithHouses` 入参强类型缺失

**位置：** `HzEnterpriseBatchController#saveWithHouses`（第 117-231 行）  
- 全程使用 `Map<String,Object>`，每个字段都 `.toString()` —— 任何字段缺失即 NPE
- 应定义 `EnterpriseBatchSaveDTO`，配合 `@Valid` + `@NotNull/@NotBlank`
- `e.printStackTrace()` 应改为 `logger.error("保存企业批次失败", e)`

### 6. 性能问题

**后端 `getCheckoutBills`（第 242-295 行）：**
- 全量拉账单后内存过滤 `"2".equals(billStatus)` —— 应在 SQL where 条件
- 循环调用 `selectEnterpriseBatchById` + `selectHouseDetailsByBatchId` + `selectCheckoutByBillId` —— 典型 N+1
- **建议改为一次 join 查询返回完整 VO**

**前端 `enterprise.vue#loadPaidBills`（第 405-410 行）：**
- 拿到账单列表后再 `Promise.all` 调 N 次 `/checkinInfo/{billId}` 拉详情
- **建议后端提供 `/paidBillsWithDetail`，一次性返回包含 projectNames/houseNos 的 VO**

### 7. 审核状态对用户不可见

`HzEnterpriseBill` 同时维护 `billStatus`（0待审核/1待支付/2已支付）与 `approveStatus`（0待审核/1通过/2拒绝）。  
小程序 `enterprise.vue` **完全没有展示 approveStatus**，导致：
- 用户提交后进入"待审核"状态，但页面看到的是"待支付"按钮 → 实际点击会被后端拒绝
- 拒绝原因（`rejectReason`）也未透出

**建议：** Tab "在线缴费"列表中：
- approveStatus=0 → 显示"待管理员审核"灰色 disable 按钮
- approveStatus=2 → 显示"审核未通过：{rejectReason}"红色提示
- approveStatus=1 && billStatus=1 → 才显示"立即支付"按钮

## 四、一般项（🟡 列入后续优化清单）

### 8. 退租流程仅二状态

`enterprise.vue` 中 `checkoutStatus` 只有 `applied/pending`。实际应有：
- 已申请 → 审核中 → 审核通过 → 工作人员联系 → 已退租 → 押金/余款结算

### 9. 缺续租入口

企业租赁周期通常以年为单位，到期前 30/60 天应有续租提示，并能基于上一批次复制生成新批次。

### 10. H5 分支绕过统一 request 拦截器

**位置：** `enterprise.vue#handleSaveCheckin`（第 580-593 行）  
H5 端走 `fetch(BASE_URL + ...)` 直接发请求，导致：
- token 失效时不会自动重定向到登录页
- 没有统一的 traceId / 错误提示
- request 拦截器若加了租户隔离也会被绕过

**建议：** 改用项目内 `request.js` 的 `uploadFile` 封装。

### 11. `enterprise.vue` 1323 行巨石

合并了"在线缴费 / 入住办理 / 退租办理"三个独立 Tab，建议拆分：
```
subpkg/service/enterprise/
  ├── index.vue          (Tab 容器)
  ├── tab-pay.vue        (在线缴费)
  ├── tab-checkin.vue    (入住办理)
  └── tab-checkout.vue   (退租办理)
```

### 12. 房源占用未校验

`saveEnterpriseBatchWithHouses` 直接 insert `hz_enterprise_batch_house`，**未校验该房源是否已被其它有效批次占用**（应排除已退租/已结束的批次）。

### 13. discountAmount 未做合法性校验

前端如果误传超大值，后端虽然兜底为 0，但 `discountAmount` 字段会落库为脏数据，影响后续报表统计。  
建议在 saveWithHouses 增加 `if (discountAmount > totalAmount) return error("优惠金额不能超过总额")`。

## 五、体验建议（🟢 视优先级跟进）

### 14. 租金明细展示
账单详情应展示明细：`房源 N 间 × 月租金 × 月数 - 优惠 = 应付金额`，便于用户核对。

### 15. 退租表单字段
当前点击退租仅一个 "确认申请退租？" Modal，建议补：
- 期望退租日期
- 退租原因（搬迁/合同到期/其他）
- 备注

### 16. 日志规范
`HzEnterpriseBatchController` 中 4 处 `e.printStackTrace()` 改为 `logger.error("xxx 失败", e)`，统一走 logback。

### 17. 人员名单校验
`submitCheckin` 仅保存文件路径，未读取 Excel 内容比对：
- 表头是否符合模板（姓名/身份证/手机号）
- 人数是否 ≤ 入住房间标准容量
- 身份证号格式
