## 一、背景

老系统（zhaohao）从 3 月份到 6 月份持续在跑，期间产生了一批新签 / 续签合同与缴费流水，但**新系统港好住**没有及时同步。老系统现已停运，不会再有新增量。

本次任务目标：
- 将 3 ~ 6 月期间的**已签约合同** + 对应的**房源出租状态**补录到新系统
- **不迁合同附件文件**（与历史 migration 一致的"仅结构化信息"策略）
- **不补建账单**（缴费列表已对账确认完整，无需重复回填）
- **不影响现有线上业务流程**

## 四、为什么这样做

| 决策 | 原因 |
|---|---|
| 用 Excel 房号定位 hid（不用合同里挂的 hid） | 部分老合同迁入时房源绑错（5 条冲突），Excel 房号是租户实际居住地的真相 |
| 续签场景保留旧合同 + 新建履行中 | 与现有 migration 数据语义一致；旧合同状态5不动，新合同状态3独立体现"在租"事实 |
| 押金统一 1000.00 | 项目业务规则（user 已确认） |
| `batch_id` 全部 NULL | 配租方式由 `remark` 字段标识；批次配租仅在有免租优惠时才写 batch_id（已迁的 36 条集中分配也都是 NULL） |
| 不补 hz_bill 账单 | 缴费列表已对账完整，再补会重复 |
| 创建 61 个 hz_user 而非用占位 0 | 现有 3717 条 migration 合同 tenant_id 均 >0，无 0 值占位；保持一致 |

## 五、回滚 SQL（保存好，应急时整段执行）

```sql
-- 1. 回滚 138 条迁入合同
UPDATE hz_contract SET del_flag='2' 
WHERE create_by='migration_2026q2_contract';

-- 2. 回滚 61 个新建租户账号
UPDATE hz_user SET del_flag='2' 
WHERE create_by='migration_2026q2_contract';

-- 3. 回滚 86 套房源状态（含主批 81 + 补丁 5）
UPDATE hz_house h
JOIN hz_house_status_bak_2026q2 b ON h.house_id=b.house_id
SET h.house_status=b.old_status, h.update_time=NOW()
WHERE h.update_by IN ('migration_2026q2_house','migration_2026q2_house_patch');

```

## 八、相关原则

- **历史迁入数据零干预**：本批仅"补"不"改"，不动任何已存在的合同/账单/退款记录
- **房号映射可靠性**：项目+楼栋+单元+房号 4 维度严格匹配 100% 命中，无歧义
- **DRY-RUN 优先 + 标签化 create_by/update_by**：每一步落库前先模拟，落库后可按标签精确回滚
