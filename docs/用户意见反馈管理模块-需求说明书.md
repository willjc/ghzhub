# 用户意见反馈管理模块 · 开发需求说明书

## 一、模块目标

开发一个可独立运行的 **用户意见反馈管理** 小模块，支持运营人员在后台接收、分类、回复、归档来自 C 端用户的意见反馈。本模块 **不涉及** 订单、合同、账单、房源、审核流转等核心业务，可独立开发、独立运行。

开发方基于若依原版脚手架从零开发，**无需** 获得任何既有系统的代码或数据。

## 三、功能清单（共 3 个页面）

```
用户意见反馈 (一级菜单)
├── 反馈分类        （分类维护）
├── 反馈受理        （接收、回复、关闭）
└── 已归档反馈      （已关闭反馈的只读查询）
```

### 3.1 反馈分类 `feedback:category`

标准若依 CRUD 列表，**单级结构，不涉及树形、不涉及多语言**。

**字段**：
- 分类编码（varchar32，必填，唯一）
- 分类名称（varchar64，必填）
- 排序号（int）
- 状态（启用 / 停用）
- 备注（可选）

**操作**：查询、新增、修改、删除、启用/停用、导出。

**规则**：
- 已被反馈记录引用的分类不允许删除，只能停用
- 在 `feedback.sql` 中预置 **5 条示例分类**：功能建议、Bug 上报、投诉、咨询、其他

### 3.2 反馈受理 `feedback:main`

**顶部查询栏**：反馈编号、分类、状态（待处理 / 处理中 / 已回复 / 已关闭）、提交时间范围、关键字（匹配反馈内容 / 联系方式）

**列表字段**：反馈编号、分类、反馈内容（截断 80 字，悬浮展示全文）、联系方式、状态、提交时间、最近回复时间

**操作按钮**：新增、修改、删除、**回复**、**关闭**、导出

**新增/编辑表单**（单页表单，不要分步条）：
- 提交用户名称（文本输入，**不做下拉、不关联用户表**）
- 联系方式（文本输入，长度 ≤ 32，**不做格式校验**）
- 反馈分类（下拉，来源于"反馈分类"启用项）
- 反馈内容（多行文本，长度 1~2000，必填）
- 附件链接（多行文本，每行一个 URL，可选，**不做上传，直接粘贴外部链接**）

**状态流转（极简）**：
- 新增时默认状态为 **待处理**，可随时修改删除
- 点击 "回复" 按钮后状态变为 **已回复**，同时在明细表中插入一条回复记录
- 点击 "关闭" 按钮后状态变为 **已关闭**，不可再修改、删除、回复
- **没有审核、没有驳回、没有撤回**

**回复弹窗**：
- 回复内容（多行文本，长度 1~500，必填）
- 点击确定后写入 `feedback_reply` 明细表，并将主表状态更新为 "已回复"
- 一条反馈可被多次回复（每次状态都是 "已回复" → "已回复"）

### 3.3 已归档反馈 `feedback:archive`

**只读列表**，仅展示所有 "已关闭" 记录。

- 顶部筛选：反馈编号、分类、提交时间范围
- 列表字段：反馈编号、分类、反馈内容（截断 80 字）、联系方式、提交时间、关闭时间
- 操作：查看详情、导出 Excel
- 详情弹窗：基本信息 + 回复历史列表（**纯表格，不要时间线、不要头像**）

## 四、数据库设计（共 3 张表）

必须提供一个 SQL 文件 `feedback.sql`（DDL + 初始化 DML 合并），MySQL 8.0 可一键执行。

### 4.1 `feedback_category` 反馈分类表
| 字段 | 类型 | 说明 |
| --- | --- | --- |
| id | bigint | 主键 |
| category_code | varchar(32) | 分类编码（唯一） |
| category_name | varchar(64) | 分类名称 |
| sort_num | int | 排序号 |
| status | char(1) | 0 启用 / 1 停用 |
| remark | varchar(500) | 备注 |
| create_by / create_time / update_by / update_time | | 审计字段 |

### 4.2 `feedback_main` 反馈主表
| 字段 | 类型 | 说明 |
| --- | --- | --- |
| id | bigint | 主键 |
| feedback_no | varchar(32) | 反馈编号（格式 `FB+yyyyMMdd+4位序号`） |
| user_name | varchar(64) | 提交用户名称 |
| contact | varchar(32) | 联系方式 |
| category_id | bigint | 分类 ID |
| category_name | varchar(64) | 分类名称（冗余，便于展示） |
| content | varchar(2000) | 反馈内容 |
| attachments | varchar(2000) | 附件链接（多个 URL 以换行分隔） |
| status | char(1) | 0 待处理 / 1 处理中 / 2 已回复 / 3 已关闭 |
| last_reply_time | datetime | 最近回复时间 |
| close_time | datetime | 关闭时间 |
| create_by / create_time / update_by / update_time | | 审计字段 |

### 4.3 `feedback_reply` 回复记录表
| 字段 | 类型 | 说明 |
| --- | --- | --- |
| id | bigint | 主键 |
| main_id | bigint | 主表 ID |
| reply_content | varchar(500) | 回复内容 |
| reply_by | varchar(64) | 回复人用户名 |
| reply_time | datetime | 回复时间 |

## 五、接口清单（共 13 个）

标准若依 RESTful 风格，返回格式用 `AjaxResult` / `TableDataInfo`；所有写操作加 `@Log` 和 `@PreAuthorize`。

| 方法 | 路径 | 功能 | 权限 |
| --- | --- | --- | --- |
| GET | /feedback/category/list | 分类列表 | feedback:category:list |
| GET | /feedback/category/{id} | 分类详情 | feedback:category:query |
| POST | /feedback/category | 新增分类 | feedback:category:add |
| PUT | /feedback/category | 修改分类 | feedback:category:edit |
| DELETE | /feedback/category/{ids} | 删除分类 | feedback:category:remove |
| GET | /feedback/main/list | 反馈列表 | feedback:main:list |
| GET | /feedback/main/{id} | 反馈详情（含回复历史） | feedback:main:query |
| POST | /feedback/main | 新增反馈 | feedback:main:add |
| PUT | /feedback/main | 修改反馈 | feedback:main:edit |
| DELETE | /feedback/main/{ids} | 删除反馈 | feedback:main:remove |
| POST | /feedback/main/reply/{id} | 回复反馈 | feedback:main:reply |
| PUT | /feedback/main/close/{id} | 关闭反馈 | feedback:main:close |
| POST | /feedback/main/export | 反馈导出 Excel | feedback:main:export |

所有接口必须带 Swagger/Knife4j 注解，可通过 `/swagger-ui/index.html` 逐个调通。

## 六、前端要求

- 新增模块目录：`ruoyi-ui/src/views/feedback/`
- 全部使用若依原生组件（el-table、el-form、el-dialog、el-pagination）
- **不需要** ECharts、**不需要** 富文本编辑器、**不需要** 文件上传组件
- 状态字段在列表中使用 `el-tag` 带颜色区分（待处理-灰 / 处理中-蓝 / 已回复-绿 / 已关闭-默认）
- 删除操作使用 `this.$modal.confirm`，不得使用浏览器原生 confirm
- 消息提示使用 `this.$message.success` / `this.$message.error`
- 菜单图标从若依自带 SVG 图标库中任选即可

## 八、开发注意事项（独立开发补充说明）

1. 直接基于若依原版脚手架，保留默认 `admin / admin123` 账号，不另建用户体系
2. 新增的菜单、权限、角色 SQL 统一追加到 `feedback.sql` 中，通过 `sys_menu` / `sys_role` / `sys_role_menu` 等表初始化：
   - 1 个一级菜单 "用户意见反馈"
   - 3 个子菜单 对应 3 个功能页面
   - 13 条按钮权限 对应接口权限标识
   - 1 个示范角色 "反馈处理员"，勾选全部权限，挂到 admin 账户下
3. **提交用户名称、联系方式、附件链接均为纯文本**，不做任何格式校验、不做任何下拉关联、不做上传组件
4. **没有** 附件上传、**没有** 审核流程、**没有** 工单流转、**没有** 统计图表、**没有** 用户评分、**没有** 站内信推送
5. 反馈编号生成规则：`FB + yyyyMMdd + 4位当日自增序号`（如 `FB202605130001`），每日 0 点序号重置，直接在后端 Service 层生成，**不做分布式 ID**
6. 状态流转规则写死在代码里（不做成配置表），按第 3.2 节的规则直接计算
7. 预置示例数据：
   - 5 条示例分类
   - 10 条示例反馈（2 条待处理 + 3 条处理中 + 3 条已回复 + 2 条已关闭，其中已回复和已关闭的记录各带 1~2 条回复历史）
