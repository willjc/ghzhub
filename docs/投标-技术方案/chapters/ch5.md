## 5.1 系统部署升级

- **标准化部署**：部署过程脚本化、文档化（部署手册随源代码交付），应用进程守护托管，故障自动拉起、开机自启；
- **发布管理**：版本升级执行"发布申请—甲方审批—低峰窗口发布—验证—公告"流程；采用可回滚发布策略，升级失败5分钟内回退上一版本；
- **灰度与回归**：重要功能升级先在测试环境完成全量回归，生产发布后执行冒烟验证清单；
- **升级留痕**：每次升级输出版本说明与升级记录，纳入运维台账。

| 2. 发布评审 | 项目经理评审变更风险；重大变更报甲方确认 | 项目经理 | 涉及数据结构变更、停机、资金链路的一律报甲方 |

## 5.2 运维制度

建立驻场运维制度体系，六项制度执行条款如下：

### 5.2.1 值班制度

1. 工作日驻场值守：驻场运维人员按甲方考勤要求现场办公，负责当日监控值守、工单响应与例行维护；
2. 非工作时间7×24小时远程响应：设置值班电话，告警自动推送值班人员；紧急故障远程处置，必要时1小时内赶赴现场；
3. 值班表每月编制并报甲方备案，调班须经项目经理批准并同步甲方；
4. 值班期间发生的事件、处置过程记入值班日志，次日晨会通报。

### 5.2.2 巡检制度

1. 日巡检：每工作日上午完成一轮标准巡检（详见5.7），填写《日巡检记录表》；
2. 周深度巡检：每周对性能趋势、慢查询、磁盘增长、证书有效期做深度检查，输出周报送；
3. 巡检发现异常按故障管理流程登记处置，重大隐患当日报甲方；
4. 巡检记录保存期与项目运维期一致，接受甲方抽查。

### 5.2.3 故障管理制度

1. 故障分级：按5.4节四级标准（紧急/严重/一般/轻微）定级，定级有争议时按高一级处理；
2. 响应与处置：紧急10分钟内响应、一般2小时内响应；处置优先恢复业务，再查根因；
3. 台账管理：全部故障录入《故障处理记录台账》（位置、问题、产生时间、解决时间、解决办法），邮件报送甲方备案；
4. 复盘改进：紧急与严重故障48小时内输出复盘报告，改进项闭环跟踪；
5. 升级机制：处置超时或影响扩大时，逐级升级至项目经理、公司二线专家团队。

### 5.2.4 备份制度

1. 每日自动备份（策略见5.11），备份结果纳入日巡检必查项；
2. 备份失败当日补备并排查原因；连续失败按严重故障处理；
3. 每季度恢复演练1次，演练报告报甲方；
4. 备份文件访问权限受控，加密存放，禁止擅自外拷。

### 5.2.5 报送制度

1. 周报送：每周输出运维工作报送（本周工作、故障与处置、下周计划）；
2. 月度运维报告：每月末前2个工作日邮件报送甲方备案，内容包括运维工作总结、故障统计分析、指标达成情况、容量与风险提示、运维建议；
3. 即时报送：紧急故障、安全事件在响应的同时立即电话+书面报甲方；
4. 报送材料统一归档，作为考核与审计依据。

### 5.2.6 交接班制度

1. 值班交接采用书面交接：未决事项、在途工单、注意事项逐项列明，接班人签字确认；
2. 人员轮换（休假、调整）时执行工作交接清单，项目经理复核；
3. 交接期间发生的事件责任界定以交接记录为准，避免"三不管"空档。

主要指标与告警阈值设定如下：

| 监控层 | 监控指标 | 告警阈值（示例基线，运行期按实际调优） |
|---|---|---|
| 服务器 | CPU使用率 | 持续5分钟>80%告警，>90%紧急告警 |
| 服务器 | 内存使用率 | 持续5分钟>85%告警 |

| 数据库 | 主从延迟 | >30秒告警 |
| 缓存 | Redis内存/命中率 | 内存>80%、命中率<90%告警 |
| 应用 | 服务存活 | 健康检查连续3次失败紧急告警并自动拉起 |

告警分三级推送：提示级（记录+日报汇总）、告警级（即时推送值班人员）、紧急级（推送值班人员+项目经理，10分钟未确认自动升级）。

## 5.4 服务响应

严格执行招标文件规定的故障响应时限，并提供多渠道7×24小时响应服务：

| 故障等级 | 定义 | 响应时间 | 解决目标 |
|---|---|---|---|
| 紧急 | 系统整体不可用、支付故障、数据安全事件 | **10分钟** | 2小时内恢复或提供应急方案 |
| 严重 | 核心业务功能不可用、性能严重下降 | 30分钟 | 4小时内解决 |
| 一般 | 非核心功能异常、页面显示问题 | **2小时** | 1个工作日内解决 |
| 轻微 | 使用咨询、优化建议 | 4小时 | 按周版本安排处理 |

响应渠道：驻场现场响应 + 热线电话 + 网络支持 + 邮件报送。故障处理完成后填写故障处理记录台账（位置、问题、产生时间、解决时间、解决办法），邮件报送甲方备案。

### 5.4.1 工单处理流程

全部服务请求（故障申报、使用咨询、数据维护、优化建议）统一纳入工单管理：

| 环节 | 处理动作 | 时限要求 |
|---|---|---|
| 受理 | 接报即建单：记录报告人、渠道、现象描述、发生时间 | 紧急10分钟内、一般2小时内确认受理 |
| 定级 | 按故障四级标准定级，通知相关责任人 | 受理时同步完成 |
| 处置 | 优先恢复业务；需开发修复的转缺陷流程；需数据维护的走数据审批 | 按各级解决目标执行 |
| 验证 | 处置完成后向报告人确认恢复，必要时测试复验 | 处置完成当日 |
| 关单 | 填写解决办法与耗时，报告人确认后关单 | 验证通过后 |
| 回访 | 紧急/严重工单一周内回访，确认无复发 | 关单后7日内 |

## 5.5 运维范围

- **应用运维**：房屋管理系统四端应用的运行保障、缺陷修复、参数配置调整、小型功能优化；
- **数据运维**：数据库性能优化、数据备份恢复、报表数据核对、按甲方审批的数据维护；
- **接口运维**：郑好办、政务核验、支付、签章、人脸、地图、监控等8类外部接口的连通性监控与异常协调处置；
- **基础运维**：应用服务器、中间件、缓存的日常维护（配合甲方基础设施团队）；
- **基础信息维护**：组织、人员、设备等基础信息维护，保障系统数据及时有效；
- **用户支持**：管理端用户常态化培训、使用答疑、操作指导，先于用户发现问题、解决问题。

**月度考核评分细则（示例，最终以甲方考核办法为准）**：

| 考核项 | 分值 | 扣分标准 |
|---|---|---|
| 故障响应及时性 | 20分 | 紧急故障响应超时1次扣5分；一般故障响应超时1次扣2分 |
| 故障解决质量 | 20分 | 超时解决1次扣3分；同一根因故障当月重复发生扣5分 |
| 巡检与备份执行 | 15分 | 漏巡检1次扣2分；备份失败未当日补备1次扣5分 |
| 报告报送 | 10分 | 周报/月报迟报1次扣2分，漏报1次扣5分 |
| 驻场考勤 | 15分 | 按甲方考勤规定执行，无故缺勤1次扣5分 |
| 培训与支持 | 10分 | 培训计划未按期执行1次扣3分；用户投诉核实1次扣2分 |
| 主动改进 | 10分 | 无当月改进项不得分；预防性发现并消除隐患酌情加分 |

月度得分低于80分为不合格，我方提交书面整改报告；连续两个月不合格无条件更换驻场人员。

## 5.7 日常维护

- **日巡检**：每工作日检查服务器资源、应用状态、接口连通性、备份结果、错误日志，填写巡检记录表；
- **周维护**：慢查询分析、磁盘清理、日志归档、证书与密钥有效期检查，输出周运维报送；
- **月维护**：性能趋势分析、容量评估、安全补丁评估、权限复核，编制月度运维报告（运维工作总结、问题统计与分析、运维建议）；
- **报表维护**：配合甲方财务口径核对收款台账等关键报表数据。

## 5.8 故障应急处置

制定分场景应急预案并定期演练（每半年不少于1次）：

| 场景 | 应急措施 |
|---|---|
| 应用服务宕机 | 进程自动拉起；无效则备节点接管，10分钟内恢复访问 |
| 数据库故障 | 主从切换预案；数据损坏时按备份恢复（RPO≤4小时，RTO≤2小时） |
| 支付渠道异常 | 启用支付降级提示，交易对账兜底，与渠道方联动排查 |
| 外部接口中断 | 资格核验自动降级人工审核；接口恢复后数据补偿 |
| 安全事件 | 立即隔离受影响节点、留存证据、上报甲方，按应急响应制度处置 |
| 高峰拥塞 | 集中配租等高峰前扩容预案、限流保护核心交易链路 |

典型场景的处置步骤卡如下，值班人员按卡执行、逐步打钩，避免紧急状态下的处置遗漏：

### 5.8.1 场景一：应用服务宕机处置卡

1. 【0-2分钟】确认告警真实性（健康检查、页面访问验证），排除误报；
2. 【2-5分钟】检查进程守护是否已自动拉起；已拉起则观察稳定性并进入根因排查；
3. 【5-10分钟】未自动恢复的，切换流量至备用节点，恢复对外服务；
4. 【恢复后】提取宕机时段日志（OOM、异常堆栈、资源曲线）定位根因；
5. 【当日】向甲方通报，48小时内输出复盘报告。

### 5.8.2 场景二：数据库故障处置卡

1. 【0-5分钟】确认故障类型：连接不可用/主从异常/数据损坏；
2. 【5-15分钟】连接类故障：重启实例或清理异常会话；主库不可用：执行主从切换预案，应用切换数据源；
3. 【数据损坏】立即停止写入，评估损坏范围，按"最近全量备份+binlog回放"恢复至故障前状态（RPO≤4小时、RTO≤2小时）；
4. 【恢复后】执行数据一致性核对脚本（账单、合同、房源状态勾稽），输出核对结果；
5. 【当日】向甲方通报，复盘并加固（如慢SQL治理、容量扩容）。

### 5.8.3 场景三：支付渠道异常处置卡

1. 【0-10分钟】监控确认支付回调成功率异常，区分我方故障与渠道方故障（渠道探测+我方日志）；
2. 【10-30分钟】我方故障立即修复回滚；渠道方故障启用前端降级提示（"支付渠道维护中"），同时联系渠道方技术；
3. 【处置中】对"用户已扣款、账单未核销"的在途交易挂起处理，禁止重复支付；
4. 【恢复后】执行专项对账：拉取渠道对账数据与我方支付单逐笔核对，差异交易按对账处理流程补单/退款；
5. 【当日】资金相关异常无论大小一律书面报甲方。

### 5.8.4 场景四：政务核验接口中断处置卡

1. 【0-10分钟】接口探测确认中断范围（单接口/全部），联系数据源侧确认；
2. 【10-30分钟】启用降级策略：资格核验切换"缓存结果 + 人工审核"模式，用户端提示"核验结果以人工复核为准"，业务不中断；
3. 【中断期间】记录降级期间产生的待复核清单；
4. 【恢复后】对降级期间数据批量重新核验，差异项转人工处置；
5. 【复盘】评估中断时长与影响面，必要时与数据源方完善联络与容错机制。

应急处置全程记录，事后48小时内输出故障复盘报告（原因、影响、处置过程、改进措施）。
