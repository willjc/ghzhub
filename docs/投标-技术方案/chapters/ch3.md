### 3.1.6 人员保障机制

- **AB角备份**：关键岗位（项目经理、架构师、核心后端）设置AB角，A角不可用时B角24小时内到岗接替；
- **二线支持**：公司总部提供架构、安全、DBA二线专家支持，疑难问题远程+现场协同解决；
- **人员稳定性承诺**：核心成员服务期内保持稳定，确需更换的提前书面报甲方审批，并完成不少于5个工作日的交接；
- **知识管理**：项目知识库（需求纪要、设计文档、问题台账、运维手册）随项目沉淀，人员交接以知识库为基线，避免知识随人流失。

### 3.1.5 人员到岗与稳定性保障

- **到岗承诺**：中标后按合同约定时间全员到岗驻场，人员名单与简历报甲方备案，关键岗位（项目经理、架构师、组长）人选与投标承诺一致；
- **人员更换约束**：关键岗位人员原则上项目期内不更换；确需更换的，提前15个工作日书面报甲方同意，替换人员资历不低于原人员，并完成不少于10个工作日交接带教；
- **考勤管理**：驻场人员遵守甲方考勤与保密规定，接受甲方月度考勤考核；
- **后备资源池**：公司为本项目建立后备人力池（开发、测试、运维各岗位），进度告警或人员突发情况时3个工作日内增援到岗，费用由我方承担；
- **知识不落单人**：关键模块实行"主备负责制"，设计文档与代码评审保证至少两人熟悉每个核心模块，避免单点人员依赖。

### 3.1.6 人员技能要求与培训

进场前完成项目专项培训并考核上岗：业务培训（三类业态政策与业务流程）、技术培训（项目技术栈与编码规范）、安全保密培训（甲方保密规定、个人信息保护要求，签署保密承诺书）。项目期内每两周组织技术分享，重点沉淀政务对接、支付对接的项目专有知识，保证团队能力与项目需求持续匹配。

## 3.2 开发规划

### 3.2.1 开发模式

采用"迭代式开发 + 里程碑管控"模式：将60日历天开发期划分为需求确认、迭代开发（3轮）、系统联调、试运行准备等阶段，每轮迭代交付可运行、可演示的功能增量，甲方全程可见、可试用、可纠偏，避免"最后一刻才见系统"的交付风险。

### 3.2.2 开发阶段规划

| 阶段 | 工作内容 | 交付物 |
|---|---|---|
| 需求确认（第1周） | 需求宣讲、原型确认、需求基线冻结、数据迁移调研 | 需求规格说明书、原型稿、迁移方案 |
| 迭代一（第2-3周） | 基础框架、登录（郑好办对接）、房源管理、首页运营位 | 可演示版本V0.1 |
| 迭代二（第4-5周） | 选房签约、合同管理（电子签章）、押金缴纳、入住办理 | 可演示版本V0.2 |
| 迭代三（第6-7周） | 退租/续租/账单缴费/开票、优惠券、服务订单、数据看板、企业客户 | 可演示版本V0.3 |
| 系统联调（第7-8周） | 政务核验/支付/人脸/地图/监控全链路联调、数据迁移演练、性能与安全测试 | 联调报告、迁移比对报告 |
| 试运行准备（第8-9周） | 缺陷修复、验收测试、培训、上线切换方案评审 | 测试报告、培训记录、上线方案 |

注：第三方接口（政务核验、支付渠道、电子签章、人脸识别）的接入申请、参数开通等外部依赖事项在第1周即并行启动，不占用关键路径。

## 3.3 开发测试与协作管理

### 3.3.1 协作机制

- **每日站会**（15分钟）：同步昨日进展、当日计划、阻塞问题；
- **每周例会**：与甲方共同评审周进度、演示迭代成果、确认下周计划，输出周报；
- **里程碑评审**：每个迭代结束由甲方参与评审，签署阶段确认意见；
- **问题台账**：需求疑问、外部依赖、风险事项统一登记跟踪，明确责任人与解决时限。

### 3.3.2 测试管理

实行"开发自测 → 提测准入 → 集成测试 → 回归测试 → 验收测试"五级测试流程：

![图3-3 测试流程图](images/27-测试流程图.png)

| 测试类型 | 内容 |
|---|---|
| 功能测试 | 依据需求跟踪矩阵逐项覆盖211项功能，用例评审后执行 |
| 接口测试 | 内部接口与8类外部接口的正向/异常/边界场景测试 |
| 业务流程测试 | 选房签约、入住退租、缴费开票等端到端全流程串测 |
| 兼容性测试 | 主流手机机型、微信版本、小程序/公众号环境、主流PC浏览器 |
| 性能测试 | 核心接口压测（集中配租选房高峰场景），验证响应时间与并发指标 |
| 安全测试 | 越权访问、SQL注入、XSS、敏感信息泄露等安全用例（详见第四章） |
| 数据迁移测试 | 试迁移记录数/金额合计/关键字段抽样三级比对 |

缺陷按严重/一般/轻微三级管理，严重缺陷24小时内修复，版本发布前严重与一般缺陷清零。

以下给出核心业务场景的测试用例样例（完整用例库随测试计划交付，预计用例总数不少于1500条）：

| 用例编号 | 用例名称 | 前置条件 | 测试步骤 | 预期结果 |
|---|---|---|---|---|

| 缺陷等级 | 定义 | 修复时限 | 发布门禁 |

| 严重 | 系统崩溃、核心流程阻断、资金计算错误、数据丢失、安全漏洞 | 24小时内修复 | 清零方可发布 |
| 一般 | 功能不符合需求、流程可绕行但体验受损、兼容性问题 | 3个工作日内修复 | 清零方可发布 |
| 轻微 | 界面瑕疵、文案错误、优化建议 | 纳入后续版本 | 登记跟踪不阻断发布 |

缺陷全生命周期（新建→确认→修复→回归→关闭）在缺陷管理工具中留痕；每周输出缺陷趋势分析（新增/修复/遗留曲线），作为版本质量放行的量化依据。

### 3.3.5 质量保证

代码走查与评审（合并前强制评审）、编码规范静态检查、单元测试覆盖核心业务逻辑、每日构建冒烟测试；质量数据（缺陷密度、修复时长、用例通过率）纳入周报向甲方透明呈现。

### 3.3.6 性能压测方案

上线前针对高风险场景开展专项压力测试，压测环境数据规模模拟生产量级：

| 压测场景 | 模拟条件 | 通过标准 |

## 3.4 配置与变更管理

### 3.4.1 配置管理

- **版本控制**：全部源代码、数据库脚本、配置文件、文档纳入 Git 统一管理；采用分支模型（主干保护+功能分支+发布分支），合并须经代码评审；
- **持续集成/持续部署**：搭建自动化流水线，代码提交自动触发编译、静态检查、自动化部署到测试环境，发布过程标准化、可重复、可回滚（该流水线为我方同类项目生产环境验证过的成熟实践）；
- **配置项标识**：版本号规范化管理，每次发布输出版本说明（变更内容、影响范围、回滚方案）；
- **环境配置分离**：开发/测试/生产环境参数外部化，杜绝硬编码，敏感配置（密钥、口令）加密管理。

### 3.4.2 变更管理

需求/设计/计划变更执行"申请—影响评估—审批—实施—验证—关闭"闭环流程：变更申请书面提出，项目经理组织评估对工期、成本、质量的影响，报甲方审批后实施，变更结果回归验证并更新需求跟踪矩阵与基线文档。紧急变更（生产缺陷修复）可先行处置、48小时内补办手续。

## 3.5 技术规范管控

- **编码规范**：Java 开发遵循业界通用编码规约，前端遵循 Vue/uni-app 官方风格指南，静态扫描工具纳入流水线强制检查；

- **接口规范**：RESTful 设计规范 + OpenAPI 3.0 文档强制同步更新，接口变更须评审并通知联调方；
- **安全规范**：敏感数据处理规范、日志脱敏规范、密钥管理规范（详见第四章）；
- **文档规范**：按 GB/T 8567 编制需求、设计、测试、部署、操作手册等全套文档，随里程碑同步交付。

### 3.5.1 编码规范细则（要点）

| 类别 | 规范要点 |
|---|---|
| 命名 | 类名大驼峰、方法/变量小驼峰、常量全大写下划线；包名按"公司.项目.模块.分层"组织；禁止拼音缩写混用 |
| 分层 | Controller只做参数校验与结果封装，业务逻辑收敛Service层，数据访问收敛Mapper层；禁止跨层调用 |
| 异常 | 统一业务异常体系，全局异常处理器兜底；禁止吞异常、禁止捕获后仅打印不处理 |
| 事务 | 事务边界在Service层声明；跨服务数据一致性采用补偿/对账机制；长事务拆分 |
| 日志 | 统一日志门面；关键业务动作INFO级留痕；敏感字段（证件号/手机号）日志脱敏；禁止System.out |
| 注释 | 类/公共方法必须有文档注释；复杂业务逻辑行内注释说明"为什么"；源代码交付注释完整可读 |
| 前端 | 组件化开发、公共组件下沉；接口调用统一封装；页面状态与接口异常统一处理；禁止硬编码接口地址 |

### 3.5.2 数据库规范细则（要点）

| 类别 | 规范要点 |
|---|---|
| 命名 | 表/字段小写下划线命名，业务前缀区分模块；索引命名含表名与字段特征 |
| 结构 | 全表必备主键与审计四字段+逻辑删除标记；金额用整型分存储；状态用字典值 |
| 索引 | 高频查询条件建复合索引；避免冗余索引；大字段拆表存储 |
| 变更 | 表结构变更走脚本+评审+版本化；生产变更在发布窗口执行并可回滚；禁止生产库手工改数据（确需修数走工单+备份+复核） |
| SQL | 禁止SELECT *；分页查询强制；大批量操作分批提交；慢SQL纳入监控每周治理 |

## 3.7 低成本、标准化实现系统互联互通

我方以"标准优先、复用优先、配置优先"三原则实现系统互联互通的低成本落地：

1. **标准化接口体系**：全部对外/对内接口采用 RESTful + JSON 统一标准，OpenAPI 3.0 文档自动生成，第三方接入无需定制开发即可完成联调，降低双方对接成本；
2. **适配器模式隔离外部差异**：支付、签章、人脸、地图、监控等外部能力均以适配器封装，更换服务商仅需替换适配器实现，业务代码零改动，避免供应商锁定带来的重复建设成本；
3. **政务接口代理网关复用**：我方已建成并在生产环境稳定运行的政务数据代理网关（统一鉴权、报文转换、缓存、降级、日志），可直接复用于本项目的资格核验与公共数据对接，节省该部分从零开发成本；
4. **成熟平台底座复用**：统一权限、字典、日志、代码生成、任务调度等平台能力为我方成熟资产，直接复用，将人力集中投入业务功能开发；
5. **模板化数据交换**：批量导入导出、数据迁移采用标准 Excel 模板 + 校验回执机制，与甲方既有办公习惯无缝衔接，无需额外采购数据交换工具。

**可复用标准能力清单**：

| 能力项 | 复用来源 | 复用方式 | 节省工作量估算 |
|---|---|---|---|
| 政务接口代理网关 | 我方生产运行资产 | 直接部署+参数适配 | 约1.5人月 |
| 支付对接组件（下单/回调/对账/退款） | 我方生产运行资产 | 适配港区支付接口协议 | 约1人月 |
| 电子签章组件（模板签署流/状态回查/存证） | 我方生产运行资产 | 适配签章服务商接口 | 约0.5人月 |
| 统一权限/字典/日志/任务调度底座 | 成熟平台底座 | 直接复用 | 约2人月 |
| 房源/合同/账单核心业务模型 | 同类平台成熟实现 | 定制化适配 | 约4人月 |
| uni-app多端工程框架 | 成熟工程模板 | 直接复用 | 约1人月 |

**互联互通实施成本对照**：以政务资格核验对接为例，从零开发需完成网络申请、协议调研、报文封装、加密联调、异常降级等全链路工作（约2人月）；复用我方代理网关模式后，仅需完成接口参数配置与联调验证（约0.5人月），成本降低约75%，且生产验证过的降级、缓存、留痕机制同步复用，质量风险显著低于新开发。

## 3.8 项目风险管理

### 3.8.3 风险升级路径

一般风险由项目组内部处置并周报通报；高风险项48小时内书面报告甲方项目主管部门，提交专项应对方案；重大风险（可能影响里程碑交付）立即启动公司级资源协调，由公司分管领导与甲方对口会商解决。

### 3.8.4 项目沟通管理计划

项目实行例行会议与报告双轨沟通机制，保证甲乙双方信息对称、决策及时：

**会议机制**：

| 会议 | 频次 | 参与方 | 主要议题 | 输出 |
|---|---|---|---|---|

| 周例会 | 每周一 | 项目经理+甲方项目负责人+各组长 | 上周交付物核对、本周计划、风险与依赖 | 周例会纪要（双方留档） |

| 报告 | 频次 | 内容要点 |
|---|---|---|
