## 简介

批量租户管理是港好住管理系统中的核心功能模块，用于实现大规模租户的统一管理和分配。该系统基于RuoYi框架构建，采用前后端分离架构，支持Excel导入、批量分配、状态跟踪等功能。

**更新** 新增批量租户动态进度跟踪功能，提供四阶段状态管理（未分配、已分配、合同已签、押金已付）和智能进度计算系统。该功能通过calculateProgressStatus()方法实现，基于租户分配状态、合同状态和押金缴纳情况智能计算当前进度状态，为批量租户管理提供可视化进度跟踪能力。

**新增** 自动状态更新机制对租户分配流程的重要影响。当批次审批通过后，系统会自动将新房源状态从"已预订"更新为"已出租"，这一机制确保了租户分配流程的自动化和一致性，减少了人工干预的需求，提高了整体运营效率。

**新增** 批量租户订单处理流程的锁定机制优化，确保批量分配用户和普通用户在锁定时间计算上的一致性。系统通过统一的锁定时间策略，为批量租户提供更合理的锁定机制，同时保持与普通用户的兼容性。该机制基于 hz_user.id_card → hz_batch_tenant.id → hz_batch_house.tenant_id + house_id 的验证流程，为批量租户订单创建提供了更强的数据安全保障。

**新增** 批量租户订单取消逻辑改进，批量租户订单取消时房源回退到'3'(修缮中)状态，保持与批次配租流程的一致性。这一改进确保了批量租户在取消订单时不会影响其他租户的房源分配，同时保持了批次配租池的完整性。

**新增** 批次配租用户锁定时间计算的动态优化，采用批次入住结束日期作为锁定时间上限，确保批量租户的锁定时间与批次配租周期保持一致。

系统主要解决以下业务场景：
- 企业批量招聘人才的房源分配
- 多项目、多批次的统一管理
- 租户信息的标准化录入和管理
- 房源与租户的精确匹配和关联
- 批量租户的特殊权限和豁免机制
- **新增** 批量租户动态进度跟踪和状态管理
- **新增** 批量租户订单处理流程的锁定机制一致性优化
- **新增** 批量租户房源归属的精确验证
- **新增** 批量租户订单取消时的回退机制优化
- **新增** 批次配租用户锁定时间的动态计算优化
- **新增** 自动状态更新机制对租户分配流程的自动化提升

### 验证方法实现

#### HzHouseOrderServiceImpl中的验证方法

```java
/**
 * 校验批次配租房源归属：该房源是否确实分配给了该用户
 * 通过 hz_user.id_card → hz_batch_tenant.id → hz_batch_house.tenant_id + house_id 三表匹配
 */
private boolean verifyBatchHouseAssignment(Long tenantId, Long houseId) {
    if (tenantId == null || houseId == null) return false;
    HzUser user = userMapper.selectById(tenantId);
    if (user == null || !StringUtils.hasText(user.getIdCard())) return false;

    // 查出该用户在 hz_batch_tenant 中的所有记录ID
    QueryWrapper<HzBatchTenant> tenantWrapper = new QueryWrapper<>();
    tenantWrapper.eq("id_card", user.getIdCard())
            .eq("del_flag", "0");
    List<HzBatchTenant> batchTenants = batchTenantMapper.selectList(tenantWrapper);
    if (batchTenants == null || batchTenants.isEmpty()) return false;

    // 检查 hz_batch_house 中是否存在 tenant_id 匹配且 house_id 匹配的记录
    List<Long> tenantIds = new ArrayList<>();
    for (HzBatchTenant bt : batchTenants) {
        tenantIds.add(bt.getId());
    }
    QueryWrapper<HzBatchHouse> houseWrapper = new QueryWrapper<>();
    houseWrapper.in("tenant_id", tenantIds)
            .eq("house_id", houseId)
            .eq("del_flag", "0")
            .last("LIMIT 1");
    Long matchCount = batchHouseMapper.selectCount(houseWrapper);
    return matchCount != null && matchCount > 0;
}
```

### 锁定时间计算优化

#### 批量租户锁定时间

批量租户采用动态锁定时间计算策略，基于批次入住结束日期：

```java
Calendar cal = Calendar.getInstance();
if (!isBatch) {
    // 普通用户：锁定10分钟
    cal.add(Calendar.MINUTE, 10);
} else {
    // 批次配租用户：截止日期为配租批次的入住结束日期(entry_end_date) 23:59:59
    try {
        BatchPreferenceVo batchPref = batchHouseMapper.selectBatchPreferenceByHouseId(houseId);
        if (batchPref != null && batchPref.getEntryEndDate() != null) {
            LocalDate endDate = LocalDate.parse(batchPref.getEntryEndDate(), DateTimeFormatter.ISO_LOCAL_DATE);
            LocalDateTime endDateTime = endDate.atTime(23, 59, 59);
            cal.setTime(Date.from(endDateTime.atZone(ZoneId.systemDefault()).toInstant()));
        } else {
            // 查询不到批次信息时回退为远期时间
            cal.set(2099, Calendar.DECEMBER, 31, 23, 59, 59);
        }
    } catch (Exception e) {
        cal.set(2099, Calendar.DECEMBER, 31, 23, 59, 59);
```

### 进度状态计算逻辑

#### calculateProgressStatus方法实现

```java
/**
 * 计算批次租户的进度状态
 * 0=未分配, 1=已分配, 2=已签订合同, 3=已缴纳押金
 */
private String calculateProgressStatus(HzBatchTenant tenant) {
    // 未分配
    if (!"1".equals(tenant.getAllocationStatus())) {
        return "0";
    }
    // 已分配，查询是否有关联合同
    if (StringUtils.isEmpty(tenant.getIdCard())) {
        return "1";
    }
    // 通过身份证号查找该批次关联的合同（batchId匹配）
    LambdaQueryWrapper<HzContract> contractWrapper = new LambdaQueryWrapper<>();
    contractWrapper.eq(HzContract::getTenantIdCard, tenant.getIdCard())
            .eq(HzContract::getBatchId, tenant.getBatchId())
            .eq(HzContract::getDelFlag, "0")
            .last("LIMIT 1");
    HzContract contract = contractMapper.selectOne(contractWrapper);
    if (contract == null) {
        return "1"; // 已分配，无合同
    }
    // 合同状态>=3（履行中）说明押金已缴纳
    String contractStatus = contract.getContractStatus();
    if (contractStatus != null && Integer.parseInt(contractStatus) >= 3) {
        return "3"; // 已缴纳押金
    }
    // 合同状态>=2（已签署）说明合同已签
    if (contractStatus != null && Integer.parseInt(contractStatus) >= 2) {
        return "2"; // 已签订合同
    }
    // 合同状态 0/1（草稿/待签署），仍算已分配
    return "1";
}
```

```java
/**
 * 释放批次关联的房源状态：将 house_status='1'（已预订）回滚为 '0'（空置）。
 * 已签合同（house_status='2' 已出租）的房源不动，避免误释放正在履约的合同。
 *
 * @param batchId 批次ID
 */
private void releaseHouseStatusByBatch(Long batchId) {
    if (batchId == null) {
        return;
    }
    // 查询批次下所有未删除的关联房源
    LambdaQueryWrapper<HzBatchHouse> wrapper = new LambdaQueryWrapper<>();
    wrapper.eq(HzBatchHouse::getBatchId, batchId)
           .eq(HzBatchHouse::getDelFlag, "0");
    List<HzBatchHouse> batchHouses = batchHouseMapper.selectList(wrapper);
    if (batchHouses.isEmpty()) {
        return;
    }

    for (HzBatchHouse bh : batchHouses) {
        HzHouse house = houseMapper.selectById(bh.getHouseId());
        if (house == null) {
            continue;
        }
        // 仅释放"已预订"，"已出租"等其他状态保持不动
        if ("1".equals(house.getHouseStatus())) {
            HzHouse update = new HzHouse();
            update.setHouseId(bh.getHouseId());
            update.setHouseStatus("3"); // 回退为修缮中（批次配租的房源来源状态）
            houseMapper.updateById(update);
        }
    }
}
```

## 结论

批量租户管理模块是一个功能完善、架构清晰的企业级应用系统。通过合理的分层设计和严格的数据模型定义，实现了高效的批量租户管理功能。

**更新** 新增的批量租户动态进度跟踪功能，提供四阶段状态管理（未分配、已分配、合同已签、押金已付）和智能进度计算系统。该功能通过calculateProgressStatus()方法实现，基于租户分配状态、合同状态和押金缴纳情况智能计算当前进度状态，为批量租户管理提供可视化进度跟踪能力。系统还新增了批量租户房源归属验证机制，通过三表匹配验证系统确保了房源分配的准确性和安全性。该机制基于 hz_user.id_card → hz_batch_tenant.id → hz_batch_house.tenant_id + house_id 的验证流程，为批量租户订单创建提供了更强的数据安全保障。

**新增** 自动状态更新机制对租户分配流程的重要影响。当批次审批通过后，系统会自动将新房源状态从"已预订"更新为"已出租"，这一机制确保了租户分配流程的自动化和一致性，减少了人工干预的需求，提高了整体运营效率。该机制通过严格的批次审批状态检查和批量房源状态更新逻辑，实现了租户分配流程的无缝衔接。

**新增** 批量租户订单取消逻辑的改进，确保批量租户订单取消时房源能够正确回退到'3'(修缮中)状态，保持与批次配租流程的一致性。这一改进避免了批量租户取消订单时对其他租户房源分配的影响，同时保持了批次配租池的完整性。

**新增** 批次配租用户锁定时间计算的动态优化，采用批次入住结束日期作为锁定时间上限，确保批量租户的锁定时间与批次配租周期保持一致。这种动态计算方式不仅提高了系统的灵活性，还增强了用户体验的一致性。
