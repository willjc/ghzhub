## 一、一分钟速览

```
港好住后端 (36.133.39.148 / 36.133.39.49)
    │
    │ POST http://42.228.16.25:8088/api/v1/gov/{业务}/query
    │ Header: X-Api-Key: lWo1XjpwMfxpPqq52bCztCP-olV-dRaL
    │ Body:   {"idCard":"xxx","name":"xxx"}
    ▼
 ghz-gov-proxy 政务代理服务（跨政务外网 + 互联网区）
    │
    ▼
返回: {"code":200,"message":"success","data":{"hasRecord":true,"records":[...],"raw":{...}}}
```

**你要做的 3 件事：**
1. 把 `http://42.228.16.25:8088` 作为 Base URL
2. 每次请求加 Header `X-Api-Key: lWo1XjpwMfxpPqq52bCztCP-olV-dRaL`
3. 读响应里的 `data.hasRecord` 判断有无记录，读 `data.records` 拿结构化数据

**4 个接口：**
| 业务 | 路径 |
|---|---|
| 婚姻 | `POST /api/v1/gov/marriage/query` |
| 社保 | `POST /api/v1/gov/social/query` |
| 公租房 | `POST /api/v1/gov/housing/query` |
| 不动产 | `POST /api/v1/gov/estate/query` |

## 二、为什么有这么多节？— 架构全景与背景

### 2.1 背景：政务数据"只能在政务外网里查"

航空港区政务数据交换平台地址是 **`59.207.50.51:4989`**，它**只在"电子政务外网"里对外开放**。互联网任何节点都 ping 不通，更谈不上调用。

而港好住业务系统部署在公有云（互联网），**两个网络物理隔离**。

这就是"为什么不能直接调"的根本原因。

### 2.2 解决方案：三层跨网架构

运维部门为我们开通了一条"**互联网 ↔ 互联网区 DMZ ↔ 政务外网**"的专线通道，配套我们部署了 3 个节点：

```
┌─────────────────────────────────────────────────────────────────────┐
│ 【L0 调用方】港好住后端                                              │
│   出口 IP：36.133.39.148 / 36.133.39.49（已加入防火墙白名单）         │
│   只能看到 → 42.228.16.25:8088（公网地址）                            │
└──────────────────────────────────┬──────────────────────────────────┘
                                   │ HTTP (公网)
                                   ▼
┌─────────────────────────────────────────────────────────────────────┐
│ 【L1 公网入口】42.228.16.25:8088                                      │
│   运维在防火墙上做了 NAT：把公网的 8088 端口 → 映射到 →                │
│   内网 172.27.139.244:8088                                            │
│   同时在防火墙里做了源 IP 白名单（只允许 L0 的两个 IP）                 │
└──────────────────────────────────┬──────────────────────────────────┘
                                   │ NAT 映射
                                   ▼
┌─────────────────────────────────────────────────────────────────────┐
│ 【L2 互联网区 DMZ】172.27.139.244:8088                                │
│   角色：Nginx 反向代理                                                │
│   作用：跨网转发——互联网区能访问政务外网的 172.19.25.77:9001          │
│   配置文件：nginx-ghz-gov-proxy.conf                                  │
└──────────────────────────────────┬──────────────────────────────────┘
                                   │ 内网跨区转发
                                   ▼
┌─────────────────────────────────────────────────────────────────────┐
│ 【L3 政务外网】172.19.25.77:9001                                      │
│   角色：ghz-gov-proxy（Spring Boot jar）                              │
│   作用：①对上提供我们自定义的 RESTful 接口                            │
│         ②向下调用政务 SDK，处理 OAuth2 Token 管理与 RSA2 加解密      │
│   这是整条链路上唯一一台"既能被互联网区访问、又能访问政务外网"的机器    │
└──────────────────────────────────┬──────────────────────────────────┘
                                   │ 仅政务外网内可达
                                   ▼
┌─────────────────────────────────────────────────────────────────────┐
│ 【L4 政务数据交换平台】59.207.50.51:4989                              │
│   由航空港区大数据管理局运营，提供婚姻/社保/公租房/不动产等 SDK        │
└─────────────────────────────────────────────────────────────────────┘
```

### 2.3 各层职责一句话说清

| 层 | 地址 | 你用它做什么 | 谁维护 |
|---|---|---|---|
| L0 | 36.133.39.148 / .49 | **你的港好住后端**，发起调用 | 港好住团队 |
| L1 | 42.228.16.25:8088 | **你要调的目标地址**，防火墙公网入口 | 政务运维 |
| L2 | 172.27.139.244:8088 | Nginx 反代，你感知不到 | 政务运维 + 王文 |
| L3 | 172.19.25.77:9001 | ghz-gov-proxy jar，你感知不到 | 王文 |
| L4 | 59.207.50.51:4989 | 政务数据源头，你感知不到 | 大数据管理局 |

**对你来说：只有 L1（公网地址）是需要记住的，其他节你不用关心。**

### 2.4 为什么不能省掉中间层？

| 假设的简化方案 | 为什么不行 |
|---|---|
| 港好住直连 L4 政务接口 | 政务外网和互联网物理隔离，包根本到不了 |
| 港好住直连 L3 的 172.19.25.77 | 172.19.25.77 没有公网 IP，互联网不可达 |
| 砍掉 L2 Nginx，L1 直接 NAT 到 L3 | L3 在政务外网，互联网 NAT 不可能直接打过去；必须先进入 L2 所在的互联网区 |
| 砍掉 L3 自研代理，让 L2 Nginx 直接转政务接口 | 政务接口用的是 **OAuth2 Token + RSA2 加签**，Nginx 做不了；必须用 Java SDK |

所以 3 层一个都不能少，这是**网络安全合规的硬要求**。

## 三、接入信息

### 3.1 核心参数（复制粘贴即可）

| 参数 | 值 |
|---|---|
| **Base URL** | `http://42.228.16.25:8088` |
| **协议** | HTTP（**暂无 HTTPS**，未来评估升级） |
| **请求方法** | `POST`（业务接口）/ `GET`（/ping 健康检查） |
| **Content-Type** | `application/json;charset=UTF-8` |
| **API Key Header** | `X-Api-Key: lWo1XjpwMfxpPqq52bCztCP-olV-dRaL` |
| **超时推荐** | 连接超时 10s，读取超时 **30s**（不动产接口可能慢到 6s） |

⚠️ **API Key 当作密码对待**：写进配置文件（如 nacos / application.yml），不要硬编码到业务代码，不要打印到日志，不要进 Git。

### 3.2 固定请求 Body 结构

所有 4 个业务接口的入参**完全相同**：

```json
{
  "idCard": "410581198610109037",
  "name": "栗毅"
}
```

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `idCard` | String | ✅ | 18 位身份证号，严格校验（政务方不接受 15 位老证号） |
| `name` | String | ✅ | 姓名，与公安系统登记一致（错一字即查不到） |

### 3.3 固定响应 Body 结构

所有接口统一返回：

```json
{
  "code": 200,
  "message": "success",
  "data": {
    "hasRecord": true,       // 布尔，是否查到记录（推荐用这个字段做业务分支）
    "records": [ ... ],      // 业务侧结构化数据（业务优先用）
    "raw": { ... }           // 原始政务平台返回，调试/兜底用
  }
}
```

| 字段 | 说明 |
|---|---|
| `code` | `200` 成功；`400` 参数错误；`401` 认证失败；`500` 服务端异常 |
| `message` | 人类可读的提示 |
| `data.hasRecord` | **业务判定首选**，true = 有记录，false = 无记录 |
| `data.records` | 业务字段已做过一层扁平化（不是所有接口都有，见下） |
| `data.raw` | 政务平台最原始的返回 JSON，含 `requestId`/`allTotal` 等 |

## 四、4 个业务接口详细规范

### 4.1 婚姻信息查询

- **URL**：`POST /api/v1/gov/marriage/query`
- **耗时**：约 0.3 ~ 1 秒
- **data 结构说明**：本接口**没有 `records`**，直接从 `data.raw.data` 数组里取

**完整响应示例**（查栗毅）：

```json
{
  "code": 200,
  "message": "success",
  "data": {
    "hasRecord": true,
    "raw": {
      "msg": "ok",
      "allTotal": 1,
      "total": 1,
      "code": 200,
      "data": [
        {
          "男方姓名": "栗毅",
          "男方身份证件号码": "410581198610109037",
          "男方身份证件类型": "",
          "女方姓名": "郭瑶",
          "女方身份证件号码": "410521198609170088",
          "女方身份证件类型": "",
          "登记证号": "J410581-2012-012044",
          "登记日期": "2012-11-28",
          "补发登记日期": "2012-11-28",
          "业务类别": "结婚登记类"
        }
      ],
      "success": true,
      "nextToken": "",
      "requestId": "177764555863074397"
    }
  }
}
```

**业务字段解读**（`data.raw.data[0]`）：

| 政务字段 | 含义 | 港好住用法 |
|---|---|---|
| 男方姓名 / 男方身份证件号码 | 丈夫信息 | 对比入参是否为 idCard 本人 |
| 女方姓名 / 女方身份证件号码 | 妻子信息 | 配偶信息来源 |
| 登记证号 | 结婚登记证号 | 留档 |
| 登记日期 | 首次登记日期 | 展示 |
| 业务类别 | `结婚登记类` / `离婚登记类` / `补领类` | **⚠️ 离婚情况要特殊处理** |

⚠️ 多条记录场景：如果有离婚再婚，`data` 数组会返回多条，按 `登记日期` 取**最新一条**。

---

### 4.2 社保缴费查询

- **URL**：`POST /api/v1/gov/social/query`
- **耗时**：约 0.3 ~ 1 秒
- **默认查询范围**：**近 12 个月**（代理服务内部自动填充 STARTDATE / ENDDATE）

**完整响应示例**（查栗毅）：

```json
{
  "code": 200,
  "message": "success",
  "data": {
    "hasRecord": true,
    "records": [
      {
        "AAC002": "410581198610109037",
        "AAC003": "栗毅",
        "AAB001": "410199922398",
        "AAB004": "郑州航空大都市研究院有限公司",
        "AAB301": "410173",
        "AAE041": "202603",
        "AAE140": "210",
        "COUNT": ""
      }
      /* ... 其他月份 × 险种组合 ... */
    ],
    "raw": { "allTotal": 33, /* 原始数据 */ }
  }
}
```

**字段说明**：

| 字段 | 含义 | 备注 |
|---|---|---|
| `AAC002` | 身份证号 | — |
| `AAC003` | 姓名 | — |
| `AAB001` | 单位社保系统编号 | 系统内部 ID |
| **`AAB004`** | **单位名称** | **⭐ 港好住核心业务字段**，做"是否在港区企业工作"校验 |
| `AAB301` | 单位所在区划代码 | `410173` = 航空港区 |
| `AAE041` | 缴费月份 | 格式 `YYYYMM`，如 `202603` = 2026 年 3 月 |
| **`AAE140`** | **险种代码** | `110` = 城镇职工基本养老<br>`210` = 失业<br>`410` = 工伤 |
| `COUNT` | 缴费次数 | 政务平台返回通常为空 |

⚠️ **跨单位缴费场景**：一个人可能同时/先后在多家单位交社保。要先按 `AAE041` 取最大月份的记录，再读 `AAB004` 确认当前单位。不要简单取 `records[0]`！

---

### 4.3 公租房查询

- **URL**：`POST /api/v1/gov/housing/query`
- **耗时**：约 0.5 ~ 1 秒

**无记录示例**（栗毅没申请过）：

```json
{
  "code": 200,
  "message": "success",
  "data": {
    "hasRecord": false,
    "raw": { "allTotal": 0, "data": [], ... }
  }
}
```

**有记录示例**：`data.raw.data` 返回数组，字段由政务方定义。港好住的业务校验逻辑**只关心 `hasRecord`**——凡已申请过公租房的人不能再申请港好住保租房。

---

### 4.4 不动产查询

- **URL**：`POST /api/v1/gov/estate/query`
- **耗时**：约 **3 ~ 8 秒**（⚠️ 比其他接口慢很多，务必调大超时）

**完整响应示例**（查栗毅）：

```json
{
  "code": 200,
  "message": "success",
  "data": {
    "hasRecord": true,
    "raw": {
      "msg": "ok",
      "allTotal": 1,
      "code": 200,
      "data": [
        {
          "SUBSYSTEMID": "航空港区",
          "FWZL": "航空港区灵鹤街9号16号楼2单元12层1203号",
          "DJSJ": "2022-08-30"
        }
      ],
      "success": true,
      "requestId": "177764560573322444"
    }
  }
}
```

**字段说明**：

| 字段 | 含义 | 备注 |
|---|---|---|
| `SUBSYSTEMID` | 子系统/区划 | `航空港区` / `郑州市` 等 |
| **`FWZL`** | **房屋坐落（详细地址）** | ⭐ 港好住核心业务字段 |
| `DJSJ` | 登记时间 | 产权登记日期 |

⚠️ 多套房产：数组多条，业务按需求处理（是否只校验港区内房产：筛 `SUBSYSTEMID=="航空港区"`）。

## 五、Java 调用示例

### 5.1 推荐方案：RestTemplate（若依框架已自带）

**① 封装常量**（建议放 `ruoyi-common` 的常量类）：

```java
public class GovProxyConstants {
    /** 政务代理服务 Base URL */
    public static final String BASE_URL = "http://42.228.16.25:8088";
    /** API Key，建议改成从 nacos/application.yml 读取 */
    public static final String API_KEY = "lWo1XjpwMfxpPqq52bCztCP-olV-dRaL";

    public static final String PATH_MARRIAGE = "/api/v1/gov/marriage/query";
    public static final String PATH_SOCIAL   = "/api/v1/gov/social/query";
    public static final String PATH_HOUSING  = "/api/v1/gov/housing/query";
    public static final String PATH_ESTATE   = "/api/v1/gov/estate/query";
}
```

**② 配置 RestTemplate 超时**（注意不动产接口很慢，读取超时要 ≥ 30 秒）：

```java
@Configuration
public class GovProxyHttpConfig {
    @Bean("govProxyRestTemplate")
    public RestTemplate govProxyRestTemplate() {
        SimpleClientHttpRequestFactory factory = new SimpleClientHttpRequestFactory();
        factory.setConnectTimeout(10_000);   // 10s 连接
        factory.setReadTimeout(30_000);      // 30s 读取（不动产接口需要）
        return new RestTemplate(factory);
    }
}
```

**③ 业务调用**：

```java
@Service
public class GovQueryService {

    @Resource(name = "govProxyRestTemplate")
    private RestTemplate restTemplate;

    /**
     * 查询社保单位
     * @return 最新月份的单位名称 AAB004，查不到返回 null
     */
    public String querySocialCurrentCompany(String idCard, String name) {
        String url = GovProxyConstants.BASE_URL + GovProxyConstants.PATH_SOCIAL;

        HttpHeaders headers = new HttpHeaders();
        headers.setContentType(MediaType.APPLICATION_JSON);
        headers.set("X-Api-Key", GovProxyConstants.API_KEY);

        Map<String, String> body = new HashMap<>();
        body.put("idCard", idCard);
        body.put("name", name);

        HttpEntity<Map<String, String>> entity = new HttpEntity<>(body, headers);

        try {
            ResponseEntity<Map> resp = restTemplate.postForEntity(url, entity, Map.class);
            Map result = resp.getBody();
            if (result == null || !Integer.valueOf(200).equals(result.get("code"))) {
                log.warn("社保查询失败: {}", result);
                return null;
            }
            Map data = (Map) result.get("data");
            if (data == null || !Boolean.TRUE.equals(data.get("hasRecord"))) {
                return null;
            }
            List<Map<String, String>> records = (List<Map<String, String>>) data.get("records");
            if (records == null || records.isEmpty()) return null;

            // 按缴费月份 AAE041 降序，取最新
            return records.stream()
                    .max(Comparator.comparing(r -> r.get("AAE041")))
                    .map(r -> r.get("AAB004"))
                    .orElse(null);

        } catch (ResourceAccessException e) {
            // 超时 / 连接不上，属于可重试异常
            log.error("社保代理服务访问异常", e);
            return null;
        } catch (RestClientException e) {
            // HTTP 4xx/5xx
            log.error("社保代理服务返回错误", e);
            return null;
        }
    }
}
```

### 5.2 备选：Hutool HttpUtil（更短）

```java
import cn.hutool.http.HttpRequest;
import cn.hutool.json.JSONObject;
import cn.hutool.json.JSONUtil;

public String queryMarriage(String idCard, String name) {

    return data.getJSONObject("raw").getJSONArray("data").getJSONObject(0).getStr("女方姓名");
}
```

## 六、错误码与异常处理

### 6.1 HTTP 层

| 场景 | HTTP Code | 处理 |
|---|---|---|
| 正常 | 200 | 继续解析 Body |
| 代理服务未启动 | Connection refused / 超时 | 告警 + 查 L3 进程 |
| Nginx 挂了 / 网络断 | 502 / 504 / 超时 | 告警 + 查 L2 |
| 被白名单拒 | Connection refused（防火墙丢包） | 确认出口 IP 在 36.133.39.148/.49 |

### 6.2 业务层（响应 Body 的 code 字段）

| code | message | 原因 | 建议处理 |
|---|---|---|---|
| 200 | success | 正常 | 解析 data |
| 400 | 缺少必填参数: idCard, name | 入参漏了 | 前端校验补齐 |
| 401 | 认证失败：无效的 API Key | Key 错或没加 Header | **立即停止重试**，检查 Header |
| 500 | 查询失败: ... | 下游政务平台异常 | 按错误信息判断，可 1-2 次重试 |

### 6.3 政务层特殊错误（在 `data.raw` 或异常信息里）

| 错误码 | 含义 | 重试策略 |
|---|---|---|
| `SHD-1004` | **连接政务平台超时** | 可重试 1 次（间隔 5s） |
| `SHD-1014` | 参数校验不通过 | 不要重试，修正入参 |
| 其他政务码 | 参考政务平台文档 | 按消息判断 |

### 6.4 重试建议（不是所有错误都能重试）

```java
// 只对"可能瞬时失败"的错误重试
boolean canRetry(Exception e, Integer bizCode) {
    if (e instanceof ResourceAccessException) return true;       // 网络/超时
    if (bizCode != null && bizCode == 500) return true;          // 下游偶发
    return false;                                                 // 其他不要重试
}
```

**不要重试的情况**：`401`（Key 错了重试也是错）、`400`（参数错，重试没意义）、`SHD-1014`（数据校验不过）。

## 七、注意事项（重要！）

### 7.1 出口 IP 白名单（部署前必须确认）

- 港好住后端**只能从 36.133.39.148 或 36.133.39.49 发起请求**，其他 IP 被防火墙丢包
- **这两台机器通常是公司出口 NAT 网关**，而不是 Pod / 容器的 IP
- 如果将来要**扩容新的服务器**或**换云服务商**，必须：
  1. 提前告知王文（确认新出口 IP）
  2. 运维向政务方提"变更源地址白名单"的工单
  3. 否则一切换就立刻全挂

### 7.2 超时设置：30 秒保底

- 婚姻/社保/公租房：< 1s
- **不动产：3 ~ 8s，偶尔更久**
- **连接超时 10s、读取超时至少 30s**；如果业务场景允许，建议 60s
- 不要用默认（某些 HTTP 客户端默认 60s，某些默认无限），显式配

### 7.3 幂等与频率

- **所有查询接口都是幂等的**，重复调用不会有副作用
- 但下游政务平台对 QPS 有限制（目前看没明确规则），**建议每用户每 10 分钟内最多调用一次同类接口**
- 结果建议**本地缓存**（见 7.5）

### 7.4 敏感信息保护

- `idCard` + `name` 是**公民个人信息**，受《个人信息保护法》约束
  - 调用日志脱敏（如 `410581********9037`）
  - 不要在前端接口响应里带回 raw（只在后端持久化时存档）
- **`X-Api-Key` 严禁泄露**，禁止出现在：
  - 前端代码、前端接口文档、Swagger 公开页面
  - 日志（打印 header 时要 mask）
  - Git（用 nacos 或 application.yml 管理，application.yml 加到 .gitignore）

### 7.5 缓存策略（强烈建议）

不动产/婚姻属于**低频变更**数据，社保月级更新，建议落库或 Redis：

| 接口 | 建议缓存时长 | 存储位置 |
|---|---|---|
| 婚姻 | 30 天 | Redis `gov:marriage:{idCard}` |
| 不动产 | 30 天 | Redis `gov:estate:{idCard}` |
| 公租房 | 7 天 | Redis `gov:housing:{idCard}` |
| 社保 | **1 天**（月初刷新） | Redis `gov:social:{idCard}` |

**业务优先读 Redis → 没有再穿透到政务代理**。节省政务方调用额度，也让你自己响应更快。

### 7.6 调用审计

港好住后端应对每次政务接口调用打审计日志（操作人、被查询人、时间、耗时、结果摘要），便于将来查数据泄露溯源。

### 7.7 并发控制

- 单个港好住 Pod 建议对政务代理的并发数 ≤ 10（连接池大小）
- 全系统并发建议 ≤ 50（避免打爆下游政务平台）
- 如果触发 `SHD-1004` 频率变高，说明压力到了，立即限流

### 7.8 健康检查

- 启动前、每次发布后可以先打健康检查确认链路通：
  ```bash
  curl http://42.228.16.25:8088/api/v1/gov/ping
  # 期望: {"code":200,"data":{"status":"UP","service":"ghz-gov-proxy",...}}
  ```
- `/ping` 接口**不需要 X-Api-Key**，可裸访问

### 7.9 协议限制

- **当前仅 HTTP（非 HTTPS）**。因为 42.228.16.25 是政务运维提供的 NAT 入口，目前没配证书。
- 传输的是公民信息，**港好住侧的调用程序建议部署在同机房/同 VPC**，不要跨公网转发
- 未来如果有 HTTPS 计划，会单独通知

## 八、FAQ

**Q1：我本地开发能调吗？**
A：不能。本地出口 IP 不在白名单，防火墙会拒。开发期可以：
  - 联系王文给你一个**开发环境模拟地址**（返回 mock 数据）
  - 或者借一台白名单机器做跳板测试

**Q2：为什么响应里 `records` 有时有有时没有？**
A：婚姻/公租房接口没做字段扁平化，需要从 `data.raw.data` 里取。社保和不动产有 `records`。规范见第四章各接口说明。

**Q3：同一个身份证查出来多条记录怎么办？**
A：
- 婚姻：按 `登记日期` 取最新
- 社保：按 `AAE041` 缴费月份取最新
- 不动产：可能有多套房产，按业务需求过滤（如只要港区的）

**Q4：`hasRecord=false` 一定代表没有吗？会不会是政务平台数据没同步？**
A：大概率代表真的没有。政务数据一般 T+1 同步。如果业务怀疑漏数据，重试前等 1 天再查。

**Q5：响应慢到 10 秒怎么办？**
A：多半是政务平台压力大，**不要立刻重试**（容易 DDoS 对方），等 30 秒再试。如果持续 > 30 秒，报给王文查 L3 日志。

**Q6：API Key 需要定期换吗？**
A：建议**半年到 1 年**轮换一次。轮换时：
  1. 我在 L3 的 `application-prod.yml` 里加上新 Key（和老 Key 并列支持）
  2. 通知港好住后端切换
  3. 等 1 周后作废老 Key

**Q7：港好住的请求数据会不会被 L2 Nginx 记录？**
A：会记 `access.log`（仅路径+IP+时间），**不会记请求 Body**（已关闭）。敏感数据不会从 Nginx 日志泄露。

**Q8：能不能加更多政务接口（比如户籍、婚姻变更历史）？**
A：可以，需要：
  1. 港好住提业务需求
  2. 我向政务方申请对应 SDK 接入
  3. 开发 + 联调后发布新版本
  4. 本文档 + 接入规范同步更新
